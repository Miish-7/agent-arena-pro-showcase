Trust boundary and decision path

Within scope. The tool reads the synthetic ticket and the read is recorded.

Trust passes from the supplied task and proposal to the server at the policy gateway. Select a component for its responsibility and handoff.

Identity

The authenticated service or operator identifies the organization and the task. Ticket text supplies data.

The gateway receives server-established context.

Proposal

The agent proposes an operation and a specific resource. A suggestion inside the ticket has no authority to change its state.

The proposal crosses into the trusted policy gateway.

Policy

The gateway compares the authenticated task, organization, resource, granted scope and current state against the applicable policy.

An independent policy decision selects the next path.

Approval

A sensitive close requires a separate authorized reviewer. The server rechecks the action fingerprint, scope and ticket revision.

A matching approval can be used once.

Tool execution

A permitted tool request reaches the local ticket service. A denied change leaves ticket state intact.

The isolated pilot exercised a real loopback TLS service.

Audit & isolation

The organization-scoped audit and exports bind the decision to the evidence. The other organization could not retrieve the report.

Integrity was verified again after restoring the synthetic database.
